Minimal Velo/API footprint (cost aware, efficient) Only implement these Velo endpoints initially GET /_functions/homeFeed — assemble hero, featured sermons, daily verse (server side for SEO). POST /_functions/sermonImport — ingest YouTube metadata (title, description, videoUrl, publishDate, uploader) and create Draft Sermon entries in Wix Data Collections. No heavy processing. GET /_functions/dailyVerse/today — return current verse for widgets and email. Optional, pay as you go features (defer until needed) POST /_functions/generateTranscript — call external STT for published sermons only. POST /_functions/podcastFeed — generate RSS if distributing externally. Why this is cost efficient Use Wix built ins for CMS, dynamic pages, media CDN, and Automations. Keep Velo functions lightweight and event driven. Avoid paid search and full transcription backlog at launch. Transcribe selectively. Cost guidance (practical, minimal) Wix costs Choose a Wix plan that includes Velo and sufficient bandwidth (mid tier). This covers hosting, CDN, Data Collections, Dynamic Pages, and Automations. External costs to budget for only if you choose them Speech to Text  (AWS Transcribe / Google Speech): pay per minute transcribed. Transcribe only published/high value sermons to reduce cost. SMS (optional) : Twilio per message if you offer SMS daily verse. Advanced search (optional) : Algolia/Elastic only if you need instant faceting; otherwise use Wix search. External serverless : only if you need heavy scheduled jobs beyond Velo limits. How to minimize spend Use Wix search and built in features first. Batch transcription and transcribe only what’s necessary. Use YouTube embeds (no video hosting cost). Use Wix Automations for email; use SendGrid only if you need advanced deliverability.
